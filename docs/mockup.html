• ทุก request ที่ต้องล็อกอิน จะแนบ Authorization: Bearer <token> และถูกตรวจก่อนเสมอ
• ตรวจข้อมูลขาเข้าด้วย zod ทุก endpoint

3. สถาปัตยกรรมระบบบน AWS

ทุกส่วนรันเป็น container บน ECS Fargate มี Load Balancer เป็นประตูหน้าคอยแยกเส้นทาง

👤 ผู้ใช้ (เบราว์เซอร์)
เปิดผ่าน URL ของ Load Balancer
↓
⚖️ Application Load Balancer (ALB)
แยกเส้นทาง: /api/* → API · อื่น ๆ → Web
↓
☁️ ECS FARGATE CLUSTER
⚛️ Web
React (build) เสิร์ฟด้วย nginx
🟩 API
Express + Prisma · JWT auth
↓
🐘 RDS PostgreSQL
ฐานข้อมูลผู้ใช้ + งาน (จัดการโดย AWS)
🐳 ทุกอย่างเป็น Container
Web และ API ถูกแพ็กเป็น Docker image เก็บบน ECR แล้ว ECS ดึงไปรัน — รันที่ไหนก็เหมือนกัน
🔄 Migration อัตโนมัติ
ตอน API container สตาร์ท จะรัน prisma migrate deploy สร้าง/อัปเดตตารางให้เอง

Deploy · 04

4. ขั้นตอน Deploy ขึ้น AWS

รันทีเดียวจบด้วย ./deploy-all.sh — สคริปต์สร้างทุกอย่างให้อัตโนมัติแบบ idempotent (รันซ้ำได้)

0
ตรวจความพร้อม 00-check.sh
เช็ก aws cli / docker และว่าล็อกอิน AWS แล้ว
1
Build & Push image 01-build-push.sh
สร้าง Docker image ของ web + api แล้ว push ขึ้น ECR (คลัง image ของ AWS)
2
สร้างโครงสร้างพื้นฐาน 02-infra.sh
VPC / Security Group / RDS PostgreSQL / ECS Cluster / Load Balancer + Target Group
3
Deploy ขึ้น ECS 03-deploy.sh
สร้าง task definition + service ให้ container รันตลอด แล้วผูกกับ Load Balancer
# ครั้งแรก — สร้างทุกอย่าง
cp deploy/config.example.sh deploy/config.sh
# แก้ DB_PASSWORD และ JWT_SECRET ในไฟล์ config.sh
cd deploy && ./deploy-all.sh
# แก้โค้ดแล้ว deploy ใหม่
./01-build-push.sh && ./03-deploy.sh
# ลบทิ้งกันโดนคิดเงิน
./99-destroy.sh
⚠️ ก่อนใช้งานจริงจัง ควรปรับเพิ่ม
ย้าย secret ไป AWS Secrets Manager · เพิ่ม HTTPS ที่ ALB · จำกัดสิทธิ์ IAM · ตั้ง desired-count > 1
